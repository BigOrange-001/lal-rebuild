# 8星装备战前战力与战斗初始校验修复

针对实际安装的1.0.4包与设备存档排查，确认三个问题，均在客户端修复。下列倍率与战力数字是开放正常8星炼金之前的定位记录；最终1.0.5另补齐8星终阶倍率，见下文。

1. `Equip` 初始化要求目标炼金阶段在配置表中存在，否则将累计系数重置为1。当前表没有8星终阶行，但服务端按已经走过的阶段累乘，例如原生6星装备的8星状态使用1.7623416832。客户端现使用相同的累计规则，保留全部已配置的阶段收益。
2. `GameMapTools.compareData` 对技能系数逐位相等比较，误报AS3与Python计算的浮点尾差。实际记录如2.0678763998000003与2.0678763997999994，以及26858.690884533302与26858.690884533273。新比较同时限制相对/绝对误差，误差上限为1e-7；不同整数、数组长度、明显系数变化及不同非有限数仍报错。
3. 竞技战出战5人，战前窗口却把导入存档的第6名成员计入预览。竞技战预览使用前5个槽位的副本；PVE、好友协助和保存阵容保持原逻辑。

同场5名英雄的生命、攻击、物理防御、魔法防御共20项全部对齐，无残留差异。主阵容包含6名、竞技战实际5名时，比较两场不同阵容的总数没有意义；竞技战窗口现显示本场5人的战力。

验证执行真实AS方法：三项专项检查覆盖浮点尾差、整数/真实差异拦截、8星装备构造和竞技5人预览；另有八星装备与既有面板/战斗属性对照三项通过。使用实际已安装APK内的SWF为基底，定向编译Equip、GameMapTools和PanelPVEembattleTeam三个类。为保持以后重建一致，将新增面板源码加入第179阶段。

最终1.0.5必须由官方ADT对最终SWF与描述文件重新打包，生成匹配的AIR内部校验文件，再与Android本地服务合并。不能直接替换旧APK中的SWF或描述文件后只重新签Android签名；这种包可以安装，但AIR会在进入游戏时拦截。合并校验同时比较ADT原包中的SWF、描述文件和内部校验文件，防止再次发布过期校验内容。

正常炼金已开放至8星，补充`8_0`阶段倍率`[1.12,1,1.0]`，不添加`8_1`、`8_2`。因此原生6星装备到8星的主要属性倍率为`1.12**6`，先前缺失终阶行时的`1.12**5`仅用于定位历史问题；旧8星存档现在也会按完整阶段表重新计算。客户端与战斗端对新增终阶倍率及旧缺行配置均有差分检查。

版本号、Android升级身份、签名与AIR内部保护文件均通过打包校验；当前进度路径保留，旧SQLite及gzip存档均可读取。配套全满存档由独立生成工具输出，不作为正式游戏的默认进度，也不提交玩家数据库。本次未操作游戏内战斗。
