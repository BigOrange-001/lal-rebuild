# 每日刷新与结算检查（2026-10-30）

## 时间来源与统一规则

玩法时间由 `GameClock.now()` 提供：服务端系统时间加持久化的管理快进偏移。通过启动脚本确认实际存档为 `runtime/local.sqlite3`，只读查询确认当前偏移为 **0 秒**。本次没有修改系统时钟、快进偏移或运行中的玩家存档。

游戏日统一使用 UTC+8：当天 **00:00:00（晚上12点／次日零点）** 起，至次日 00:00:00 前。中午不切换游戏日。23:59:59 属于当前游戏日，次日 00:00:00 属于新游戏日。所有日期键、相邻日判断及月度签到均采用这一分界。

刷新在跨界后的下一次相关读取、写入或登录时落实，不依赖服务启动时长，不要求玩家退出重登。竞技排名日奖在新游戏日的首个认证请求时按上一游戏日结算，保留原有参与记录、去重邮件和已结算标记；不会因重试重复发放。

## 检查与修正范围

| 项目 | 处理 |
|---|---|
| 普通／精英及非材料活动关卡限次 | 新建每日挑战计数，与累计通关记录分离；零点恢复额度，保留首通、星级、塔进度与累计任务依据 |
| 材料活动／远古试炼 | 共享胜利次数及购买次数采用统一游戏日，跨零点完成的战斗按结算日扣次 |
| 探险 | 刷新、购买、复活等每日记录采用统一游戏日，修正登录读档中单独按零点重置的代码 |
| 体力购买 | 每日购买计数零点归零；自然体力、碎片体力仍按原有时间间隔恢复 |
| 竞技 | 每日奖励场次数、排名参与日期和上一日结算按零点划分；累计 PvP 次数不清空 |
| 公会／首领 | 每日捐献、膜拜、免费挑战等沿用各功能状态，通过共享游戏日统一切换 |
| 签到／月卡／基金 | 每日领取、连续签到和月度签到使用同一日界；月切换也在当月1日零点，累计签到总数保留 |
| 每日任务／抓宝／福利／转盘／兑换 | 每日任务、免费资格、领取标记与每日兑换名单随共享游戏日切换 |
| 友情免费召唤／助战 | 补齐免费召唤日次数及双方助战记录的日刷新；原有免费召唤冷却不缩短 |
| 消费额度／在线候选人轮换 | 从独立零点／UTC日计算改为共享零点分界 |

限时活动的明确开场时段、固定持续时间、月卡有效期、登录会话有效期和战斗凭证有效期仍按其原有时间规则运行，不能用每日刷新代替到期判断。非日重置的活动总进度、付费保底、累计 PvP 和通关记录不清空。旧档缺少新增每日标记时，首次采用新规则保留已使用次数，之后正常每日刷新。

## 客户端与构建

- `Tools` 的“是否同一天／相邻天”采用服务端 UTC+8 零点分界；消费界面按同一策略刷新。无缓存配置时也默认零点。
- 连续签到界面使用当前同步的服务端时间，避免在线跨零点后仍拿登录时刻判断。
- 关卡限次读取独立每日计数，过期的前一日界面快照显示为未使用；正式扣次仍由服务端校验。
- 最后的 `GlobalFunction` 构建阶段保留叶方法替换，纳入 `getUserCombat`。仅显式开启“允许常量池追加”：逐项验证旧常量池前缀字节完全相同，旧索引不变，继续拒绝签名、方法／类索引依赖及非叶方法改变。
- 实际编译并检查了 Tools、消费界面、签到界面和 GlobalFunction；验证其它 **12,038** 个方法体字节不变。刻意篡改已有常量会被拒绝，且不生成输出。没有用重新编译整类来替换无关闭包。
