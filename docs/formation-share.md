# 阵容分享与挑战

竞技场新增“导出阵容”“导入敌阵”按钮，以及“阵容挑战”栏目。

1. 点击“导出阵容”，使用原来的竞技场布阵页选择队伍、安排站位，点击“导出”，复制完整代码。
2. 点击“导入敌阵”，粘贴完整代码并保存。可以导入他人的阵容，也可以导入自己的阵容。
3. 导入的阵容使用原竞技场列表样式展示，可以挑战或确认删除。同一代码重复导入不会增加重复项。

导出的是当时实际出战的最多五名英雄的完整战斗属性、站位、技能和羁绊。未出战的第六个队伍位置不参与羁绊计算。之后培养英雄、换装不会改变已导出的阵容。导出代码不包含密码、登录凭证或资产背包。

阵容库按账号保存在 `formation_library` 表，覆盖升级和普通重启不会清除，也不参与竞技场对手刷新和过期清理。数据库存档备份会同时保留阵容库。主动切换到更早的存档仍会恢复该存档当时的阵容库。

阵容挑战复用原布阵、战斗引擎和战斗确认机制，但使用独立的 `formation` 战斗类型。不消耗竞技场次数或体力，不改变排名，不发放奖励，战斗结束返回阵容挑战栏目。删除阵容不影响已发起战斗的结算。

代码以 `LALF1` 开头，包含有长度上限的压缩快照和完整性校验。小数按 IEEE 754 双精度编码，避免 Android ARM 转译环境的十进制解析误差破坏快照。配置兼容性签名和技能校验容许极小的 CPU 舍入误差，实际技能配置变化仍会拒绝。不同战斗配置的代码不能直接导入或挑战；已保存的不兼容阵容仍可见、可删除。

接口：`user.export_formation`、`user.import_formation`、`user.list_formations`、`user.delete_formation`、`user.pk_combat_formation`，以及已有的 `user.battle_finish`。

验证范围：`server/test_formation_share.py` 覆盖只读导出、持久保存、重复导入、冻结属性、镜像站位、账号隔离、自我挑战、删除时在途战斗、损坏代码、体积限制、配置变化、小数精确保留，以及真实 AMF 请求全流程。原竞技场网关、日常奖励与战力测试也应通过。

客户端沿用主分支 1.0.5 的源码链与资源，使用每个类最后生效的源码（特别是 `163_UiLayer.as`），新增第 180 阶段保留原布阵页面的最终实现。发布时保存基线哈希、改动源码哈希和最终 SWF 哈希；修改源码后必须重新编译和打包。
