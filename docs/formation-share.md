# 阵容分享与挑战

竞技场的“阵容挑战”栏目集中了全部阵容功能，其他竞技场栏目保持原样。

## 使用

1. **挑战自己**：点“导出我的阵容”，在原竞技场布阵页选队伍、排站位，点“导出阵容”。回到阵容挑战栏后弹出导出窗口，可以填写阵容名称（最多16字），然后：
   - “保存并去挑战”：直接保存到列表，不用复制粘贴；
   - “复制阵容码”：复制代码发给好友，改过名称时复制的是新名称的代码。
2. **挑战好友**：点“导入阵容码”，粘贴以 `LALF1` 开头的代码（聊天软件里夹带的前后文字会自动忽略）。名称可选填，留空就用原名称。
3. 列表每行显示：名称、导出时间、作者与等级、五名英雄、战力、战绩（胜负场数和上次结果）。点“挑战”进入布阵，点“更多”可以复制阵容码、重命名或删除。
4. 战斗结束返回阵容挑战栏，战绩自动更新。列表为空时会显示“挑战自己”“挑战好友”两张引导卡片。

## 规则

导出的是当时实际出战的最多五名英雄：完整战斗属性、站位、技能等级和羁绊。未出战的第六个队伍位置不参与羁绊计算。之后培养英雄、换装都不会改变已导出的阵容。代码里没有密码、登录凭证和资产背包。

**跨版本兼容**：导入和挑战只检查阵容里的英雄在当前版本是否存在。属性和站位按导出时的数值保留；技能按导出时的等级，用当前版本的技能配置重建；战力按当前公式重新计算；当前版本已删除的天赋会被忽略。战斗规则和数值调整不会让已保存的阵容失效，也不会提示版本差异。只有英雄或其主技能在当前版本不存在时，这一行才会显示“不可用”，但仍可删除。第一版代码里的规则签名和战力字段会被忽略，所以旧代码照样能导入。

阵容挑战使用独立的 `formation` 战斗类型：不消耗竞技场次数和体力，不改变排名，也不发放奖励。删除阵容不影响已经开打的战斗结算，只是不再记录战绩。

## 存储

阵容库按账号保存在 `formation_library` 表，每行带 `wins`、`losses`、`last_result`、`last_at` 战绩列（旧数据库启动时自动补列）。阵容的 ID 只由英雄快照决定，与名称无关：同一阵容再次导入不会新增一行，填了名称时会改名。覆盖升级和普通重启不会清除阵容库；它不参与竞技场对手刷新和过期清理。数据库存档备份会同时保留阵容库；切换回更早的存档，会恢复那份存档当时的阵容库。

代码以 `LALF1` 开头，内容是压缩的快照加完整性校验，体积有上限。小数按 IEEE 754 双精度编码，避免 Android ARM 转译环境解析十进制时出现误差。

## 接口

`user.export_formation`（可选 `name`，`save: true` 时同时保存）、`user.import_formation`（可选 `name`）、`user.list_formations`、`user.rename_formation`、`user.formation_code`（按 `formation_id` 或 `code` 重新生成代码，可选 `name`）、`user.delete_formation`、`user.pk_combat_formation`，以及已有的 `user.battle_finish`（返回 `formation_record`）。

## 验证

`server/test_formation_share.py` 覆盖以下场景：只读导出、持久保存、重复导入、冻结属性、镜像站位、账号隔离、自我挑战、删除时在途战斗、损坏代码、体积限制、规则变化后照常挑战、英雄缺失时不可用、命名/改名/重新编码、聊天文本夹带代码、战绩只记一次、小数精确保留，以及真实 AMF 请求全流程。

## 客户端集成

客户端源码由 `scripts/sync_formation_share_104.py` 集成，用到 `client/src/formation_share_104.aspart`（阵容挑战栏与弹窗）、`formation_item_104.aspart`（列表行）、`formation_map_104.aspart`（导出请求）。脚本可以在功能加入前的源码上重放，结果与仓库源码一致。修改源码后必须重新编译、打包。
