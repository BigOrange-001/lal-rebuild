# 英雄平衡、技能成长与新年安妮修正

本次提交包含英雄平衡配置、可复现的离线强度测试工具、技能等级成长修正，以及新年安妮召唤物修正。历史强度结果与后续技能修改分别记录，修改后的配置没有再次进行完整胜率复测。

## 最终行为

- 强度测试默认每名英雄独立统计 1,000 场，作为其他英雄队友或对手的出场不计入；支持总榜和普通／皮肤分别榜。平局按半胜计入，增加平均伤害、治疗、抗伤占比。
- 后续强度测试排除 JY大魔王、伊芙蕾雅、Miss大小姐、小智四类解说卡。一图流直接列出结果；历史海报使用既有测量数据筛选，不能作为后续加强或修正后的新测量结果。
- 平衡配置保留六轮迭代及后续普通阿卡丽技能 +10%。统一技能系数成长为 `1级值 × (1 + (等级 - 1) / 9)`，覆盖原技能、英雄羁绊、装备羁绊组合；时间、距离、数量、触发条件保持机制定义。
- 新年安妮改为召唤橙阶新年熊 `A_2020_6`，普通安妮继续使用 `A_2002_5`。通过 `hero_C.swf` 的导出符号和位图确认新年熊美术；熊存活时复用，死亡后重召。
- 新年安妮全部技能系数额外提高 10%，在羁绊及装备变体生成后应用，包含召唤面板、治疗、被动指令、护盾和宠物成长。37 个技能变体的 810 个逐级数值与修改前逐项核对，均为 1.1 倍。英雄自身面板不变。

队长技与被动保留现有固定 1 级使用规则，同时配置完整的 1～10 级曲线；本次不新增对应升级入口。两倍关系是技能系数关系，最终实战结果还受属性、缺失生命、触发与上限影响。

## 验证

基于合并 PR #25 后的 `main` 在独立检出目录验证：81 项技能、原生方法、羁绊、显示及统计回归通过；另 7 项平衡与独立采样回归通过，共 88 项。测试基线直接从仓库配置生成，不依赖本机历史对战文件。

等级审计检查 3,610 个技能配置、13,076 条数值曲线的 130,760 个逐级值；执行客户端实际等级方法的 36,100 个技能／等级组合与服务端一致。原生皮肤检查包含 39 个战斗／状态场景。

修改过的 Avatar、SkillSet 均通过 FFDec 编译。独立检出中的对应源码与已编译源码哈希一致，并同步 `client/build.json`。未重新打包 APK、安装客户端、重启游戏服务或进行 AIR 实机对战验收。

## 工具和历史数据

离线强度工具需要 Python QuickJS 绑定（提供 `quickjs.Context`）；一图流需要 Pillow 和 Windows 微软雅黑等字体。原生方法测试需要 Node.js。游戏服务不依赖这些离线工具库。

项目提供的环境中先加载 `..\env.ps1`，并让 `PYTHONPATH` 指向当前检出的 `server`、`scripts`。主要入口：

- `scripts/run_hero_strength_independent_104.py`：独立受测英雄采样。
- `scripts/verify_hero_strength_independent_104.py`：对逐场记录重新计数。
- `scripts/audit_skill_rank_growth_104.py`：导出当前配置的完整 1～10 级 CSV 和审计结果。
- `scripts/build_hero_strength_poster_104.py`：从历史测量结果生成一图流。

`outputs/` 下的逐场记录、冻结配置、图片和编译产物保留在本地，不随代码提交。历史结果见 `hero-balance-iteration-20261030.md` 和 `hero-strength-independent-20261030.md`，技能成长细节见 `skill-rank-growth-20261030.md`。其中历史报告的胜率和目标达成情况只适用于报告对应的冻结配置；最后两次技能加强、成长和召唤绑定修正后的胜率仍待新测。
