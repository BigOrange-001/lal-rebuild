# 1.0.3 英雄机制与通用事件被动创作接口

状态：开发代码，待审查与用户验证。此次按用户要求不运行测试、战斗或打包。来源为 GitHub 游戏 1.0.3 main；不包含其他工作副本的未提交修改。

## 游戏基线与模板

编辑器通过与游戏工具共享的 `mod_authoring_103.apply_mod_authoring_103` 顺序加载召唤说明、技能书、英雄修订、天赋、平衡、DOT和四组皮肤技能。纯数值快照函数抽到 `native_skill_snapshot.py`，游戏仍从原模块重新导出同一函数；离线编辑器不需要导入战斗模拟器或启动网关。

当前投影包含 1207 个技能、83 种原生动作、52 个复合机制。限时神佑、纯最大生命治疗、施法者攻击护盾、穿甲／灼烧技能书，以及悟空、莫德凯撒、猫女卡特琳娜、极地艾希、圣诞维嘉、护士阿卡丽的当前技能，均可从原生模板库导入。技能书的事件被动和专属状态机入口作为独立事件节点保留，不允许与普通动作混为一张被动动作表，避免引擎只读取首节点而忽略后续内容。复合主动技能仍可按动作顺序组合；当前动作数组决定其参数，不再固定读取技能第一项。

编辑器展示新增数值的含义，沿用引擎既有状态机语义。原生模板保留来源摘要，改过的原版技能需要重新导入核对；不会静默替换旧工程内的作者数值。原生模型的新快照标记 `runtimeVersion: "1.0.3"`；旧模板不强行添加该标记，仍经过原有摘要和参数边界检查。

## 事件被动

在效果序列模型中选择 `trigger.kind: "event"`，技能绑定英雄的 passive 槽。主动／队长槽绑定事件技能会被编译器拒绝，避免静默不触发。每个技能选择一个事件。

| event | 触发时点 |
| --- | --- |
| turn_start | 自身行动机会开始，回合前被动阶段 |
| turn_end | 自身行动结束，后续行动开始前 |
| basic_attack | 完成一次普通攻击，包括未命中；不把每个群攻目标算成一次普攻 |
| skill_cast | 完成一次主动技能或队长／装备技能，不将事件被动自身算成主动施法 |
| hit | 一次攻击命中；被护盾完全吸收仍算命中 |
| crit | 一次攻击命中且暴击 |
| miss | 自身攻击未命中 |
| dodge | 闪避了对方攻击 |
| damage_taken | 存活者实际损失生命后，不含护盾吸收量和过量伤害 |
| damage_dealt | 对目标造成实际生命伤害后，包括持续伤害 |
| healed | 自身获得一次正数治疗请求，支持实际恢复为0但存在过量治疗 |
| heal_done | 对一个单位施加一次治疗，群体治疗按目标独立发生 |
| kill | 致死保护／神佑等处理完后，最终击杀敌方单位 |
| death | 最终死亡后、退场前；可影响其他活单位，不隐式复活自身 |
| shield_break | 自身护盾被伤害耗尽，不把主动驱散护盾算击破 |

事件数值读取结算结果。护盾、神佑、免死等保护先结算，再判断最终击杀与死亡。相互依赖的事件按实际结算顺序同步执行；同一个被动只能选择一种事件，不据此推导一个跨事件全局总排序。原生专属被动继续使用原实现。

### 筛选与冷却

- `relation`: any / self / ally / enemy。关联单位为事件来源；当来源就是施法者时，改用事件目标。ally表示其他友军。
- `unitType`: any / hero / summon，筛选关联单位。
- `minAmount`: 最低实际伤害或恢复量；过量治疗单独提供。填0可处理纯过量治疗。
- `hpBelow`: 自身生命比例不高于此值，0～1。
- `requiredBuff` / `absentBuff`: 自身必须持有／缺少的状态，不接受同一状态的矛盾设置。timed_bless检查限时神佑，bless检查神佑状态。
- `maxPerRound`: 每个全局回合最多触发1～16次，默认1。
- `warmup`: 从本次战斗开始，经过多少自身行动机会后就绪；0允许在首次行动前响应事件。
- `cooldown`: 0～100个自身行动机会。0允许本回合再次响应，但仍受maxPerRound限制。非事件效果技能仍要求至少1。
- `allowChain`: 默认false，不响应通用事件被动执行期间产生的后续事件。开启后允许其他被动连锁；同一个被动仍不能重入，最多8层，单次链最多执行64个被动。额度在执行前占用，不能通过击杀连锁绕过。普通英雄无此类被动时不进入新结算路径。

### 事件目标与数值

`target: event_source / event_target` 分别引用事件来源和目标，空引用、已死亡单位或与动作阵营不符的单位被跳过。治疗／增益作用于友军；伤害、位移、诅咒等作用于敌军。仍可使用原有自身、全队、全敌和前序目标等选择器。

治疗／护盾在原有攻击和最大生命系数上叠加：`eventRatio × 事件实际量 + overhealRatio × 事件过量治疗量`。伤害同样支持这两个数值来源，并沿用所选伤害类型的命中、暴击、护盾和防御规则。复现护士原版不判定命中／暴击的固定反击时，应导入其 `nurse_healing` 原生模板。

两个事件系数均支持线性等级成长，说明分别引用 `{rank:动作索引:18}` 和 `{rank:动作索引:19}`。旧效果技能继续编译为18列；事件技能编译为20列，额外参数不能偷偷加入非事件技能。旧神佑bless保持永久语义，新增timed_bless按持续回合设置限时神佑；两者沿用1.0.3的覆盖和消耗规则。

以下技能表示受到实际生命伤害后恢复其25%，零冷却、每全局回合最多3次，默认不被被动连锁触发：

```json
{
  "id": "wound_recovery", "name": "受伤恢复", "description": "受到伤害后恢复部分生命。",
  "model": "effect-sequence-v1", "warmup": 0, "cooldown": 0, "range": 3000,
  "trigger": {"kind": "event", "event": "damage_taken", "minAmount": 1, "maxPerRound": 3, "allowChain": false},
  "actions": [{"type": "heal", "target": "self", "eventRatio": 0.25}],
  "rankInfoTemplate": "受到伤害后恢复实际损失生命的{rank:0:18}。", "maxLevel": 1
}
```

## 兼容能力与交付

新1.0.3模板或限时神佑要求 `skill.native-template.103`；事件技能另外要求 `skill.events.v1`。导出器自动声明，服务端编译结果包含 requiredClientCapabilities，客户端请求声明支持。未更新的正式1.0.3客户端仍不具备新的通用事件接口；需要构建包含本次改动的客户端后使用，不能删掉能力声明绕过校验。

游戏与编辑器分别提交PR，先合并游戏接口再合并编辑器。当前源码不等于已发布的EXE/APK；本轮只完成静态语法、Schema生成、来源与契约核对，未进行功能测试或实机验收。
