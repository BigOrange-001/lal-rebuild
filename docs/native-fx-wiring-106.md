# 原版特效接线盘点（1.0.6）

分支 `feat/native-fx-wiring-106`，基于 `feat/hero-code-fx-106`（b3a65c0）。

## 结论

- 原版技能特效全部在主 SWF 内嵌的 DragonBones 库 `effectDB` 里，共 98 个 `effect/eNNN` 动画。原版的“技能 → 特效”表已经丢失，`EffectManager.initData` 只剩 `E_001`–`E_019` 这几条无法播放的旧字符串列表。现在用的特效表是项目重建的（`FX60_*`、`FX_S9xxx_*`、`FX_A_<英雄>_*`），所以有些英雄的专属动画一直没人引用。
- 本次接上了 3 个能确定归属的专属动画，另外补了 1 个缺失的特效表条目：
  - **拉克丝·终极闪光**：金边白色光束 `e602`，配圆形光头 `e504`（第一个确认的样例）。
  - **阿狸·魅惑灵弹**：红心 `e521`。
  - **崔斯特·万能牌**：火焰纸牌 `e519`。
  - **`FX60_BURN`**：装备羁绊的灼烧动作引用了这个名字，但特效表里一直没有这一条。
- 第二轮（用户授权按理解分配）：其余 15 个“看着像”的闲置动画按外观和技能设定逐个分配，接到 15 名英雄身上；凯尔大招原来完全没有画面，补上了金色圣罩。详见[第二轮接线](#第二轮接线)。闲置的英雄向素材至此全部用上，剩下的闲置动画都是通用或系统素材。
- `feat/hero-code-fx-106` 已经用代码重绘或认领的英雄一律不动。表中标“已由代码特效覆盖”。
- 未上机：本机没有模拟器，只做了配置构建、离线素材检查、渲染预览和关联测试。

## 特效链路

1. 技能配置 `cfg.skill[S_…].skill` 是动作列表，每个动作最后一项是特效名。例如 `["damage", 3.12, 2, "FX_A_1060_MAGIC"]`。客户端写死的六星技能（`manual_ability`）用 `action[3]` 作为特效名。
2. 服务端在 `gateway.build_static_config` 里依次叠加各个覆盖模块，得到最终的 `cfg.effect` 和 `cfg.skill` 并下发。客户端把 `cfg.effect` 存进 `GlobalData.$mConfig_effect`，由 `EffectManager` 加载。
3. `DisplayTools.getAttrs(特效名)` 返回特效条目。`Avatar.attack` / `SkillSet.checkAttack` 按条目字段播放：
   - `pre`：施法者身上的前摇。
   - `b`：弹道，从施法者飞向目标。
   - `p`：弹道路径。`w:1` 拉伸到目标；`w:3` 是随飞行时间伸长、结束时收窄的光束；`w:0`/`w:2` 是沿途撒点。
   - `ps`：粒子拖尾。
   - `h`：命中，在受击时播放。
   - `sp`：弹道速度，默认 800。命中等待时间等于距离 ÷ `sp`（至少 0.25 秒）。
4. 条目里的 `id` 以 `e` 开头时，`DisplayTools.newDisplayObject` 会用 DragonBones 在 `effectDB` 里构建 `effect/eNNN`。带 `xml` 的走粒子（`textures/1x/particle/pxNN.pex`），带 `img` 的走贴图。
5. 已有做法：状态类特效由 `server/battle_status_effects.py` 在加载时覆盖特效表（`burn`、`GANK` 等）。本次沿用同样方式，新增 `server/native_fx_wiring_106.py`，放在所有复制技能的覆盖模块（深渊档位、技能书）之后执行，让副本也带上同样的特效。
