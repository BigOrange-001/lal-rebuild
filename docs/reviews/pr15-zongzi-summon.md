# PR #15 粽子召唤修复与合并检查

检查时间：2026-10-18。基线为 PR 最新提交 `cfdf8019e464b0dc74ef11cf8f8094e7a2ccda94`（v6）；检查结束时 PR 仍为 Open，未合并。本修复分支基于该提交，未修改投稿人的分支。

## 确认的问题

- v6 已把客户端每路限制改为 3，服务端为每主人全场 3，仍不一致，且违反本次指定的每路 2 个规则。
- 相邻分路计数从 -1 开始，会少计一个存活粽子；候选分路全满时仍回落到已满本路。
- 客户端用 1..3 判断分路，实际地图使用 0..laneCount-1，可能漏掉 0 号路或选到不存在的分路。
- 客户端在全场上限时可替换旧粽子，服务端停止召唤。
- 粽子飘香客户端用施法者自己的存活召唤家族计数，服务端原先计入所有友军召唤的粽子。

## 修复后的共同规则

限制沿用客户端的每主人召唤家族：每路最多 2 个、全场最多 6 个，死亡粽子不占名额。优先本路；本路满时，从有效且未满的相邻分路随机选一条。两个相邻分路都满时停止本次召唤，不越过相邻分路寻找远端空位。达到全场上限时停止，不替换或杀死旧粽子，也不触发由替换造成的数量变化事件。死亡后按同一选择规则补召。

异路落点为该路最靠前存活友军前方 50 码，空路回退到原召唤目标位置前方 50 码；两侧阵营方向对称，落点仍经原地图边界方法限制。客户端从 winnerList 取得真实分路数；服务端新增可选 lane_count，缺省从初始双方阵容推断。若快照没有覆盖地图所有分路，模拟调用方应传入真实 lane_count。

粽子飘香沿用客户端已有行为：增益和治疗系数乘以 `1 + 本主人存活粽子数`，继续作用于所有分路友军。其他主人的粽子和已死粽子不放大系数。其他英雄的召唤分支、上限与替换策略未改动。

另外同步了 client/build.json 中 Avatar/SkillSet 的源码摘要，使构建清单包含 PR 最新 Avatar 源码及本次 SkillSet 修复。
