# 1.0.3 装备标定及技能书开发记录

已按用户确认的映射完成开发，尚未打包发布或实机验收。

## 标定数据

`config/reconstruction/equipment-calibration.json` 原样保留用户的 `装备标定-1.0.3.json`，共 256 条定义，标记 152 个修改 ID。启动网关后应用名称、类别和属性，不改写玩家装备实例或清空存档。88 本技能书运行时追加品质后缀，各用自己的新技能定义，避免复用旧攻击技能造成串改。

符印百分比按 `(品质编号 + 1) × (技能等级 + 5)%` 计算，1～10级：白18%～45%、绿24%～60%、蓝30%～75%、紫36%～90%、橙42%～105%、红48%～120%。非伤害之书为两倍，自身增益持续1回合，每3回合释放。

精准、闪避、暴击、韧性分别提高对应属性。力量提高总攻击力，钢铁提高总双防，两者按上述常规比例的四分之一乘算。例如白色1～10级为4.5%～11.25%，包含英雄、培养、装备、命运、公会研究等基础面板来源。

破甲额外提高对护盾的伤害；加成只用于消耗护盾，不直接放大穿盾后的HP伤害。裂甲忽略目标一定比例的双抗，穿透上限100%；裂甲之书每3回合给自己添加两倍比例的穿透，持续1回合，属于可驱散、可被诅咒阻止的增益。

火焰符印只由普攻命中触发，灼烧总量为本次实际扣血×比例，分3回合结算，每次攻击独立叠加；取整余数分配到后续结算，不丢失总量。复苏只提高佩戴者施放的治疗量，不增加其受到的他人治疗。魔灵也由普攻命中触发，诅咒持续3回合；现有最高品质紫色满级为8%，其他品质/等级按常规曲线等比例缩放。闪避、无实际扣血或已死亡目标不触发攻击符印；灼烧与技能伤害不会递归触发。

火焰之书对当前分路全部敌人造成真实伤害，再施加每回合100%攻击、持续3回合的灼烧。当前最高品质为紫色，其1～10级直接伤害110%～200%；绿色按4/6、蓝色按5/6缩放。守护为当前分路全部友军（含自身）提供相当于火焰直接伤害加完整灼烧伤害的护盾，持续3回合，紫色满级基础值为500%攻击。两者准备1回合、间隔5回合（第2、7、12个自身回合释放）。

## 概率升级

采用用户确认的“消耗材料，尝试升1级”。每次1～5本材料；成功、失败均消耗材料和金币。满10级拒绝扣费；材料不能为自身、重复实例、已装备、锁定或待处理洗练的装备。同名但不同实例的书可以作为材料。

按用户确认的公式，1升2时每本材料贡献：灰10%、白20%、绿30%、蓝40%、紫50%、橙60%、红70%。目标当前等级每比1级高1级，每本贡献减3个百分点，单本最低0%，合计最高100%。例如2升3：白17%、绿27%；3升4用一本绿书和一本橙书，成功率为24%+54%=78%；9升10白书0%、绿书6%。前后端使用同一份基础贡献和等级递减参数；满10级不允许升级。金币仍按原界面规则：当前技能等级×目标品质编号×`skill_book_exp[5]`。

客户端每次提交材料ID快照；回执清理已消耗实例、重算材料/成功率/金币并刷新面板，概率失败给出明确提示；迟到回执不清掉新目标的材料。服务端 actionID 重放复用原结果，避免重复扣费或重新掷骰。

## 验证与限制

`server/test_skill_books.py` 覆盖标定、连续升级、失败后重试、重放、原子拒绝、属性顺序、品质曲线、增益周期、分路灼烧和护盾；`scripts/test_skill_books_client.py` 执行真实 AS 方法，覆盖连续回执、迟到回执、材料清理、概率计算和面板/战斗缓存不重复加成。

另执行装备、战斗、诅咒和召唤物属性继承的既有回归。客户端战斗改动应用到最终覆盖版本 `137_Avatar.as`，保留较早的 `079_Avatar.as`，避免后续构建覆盖本次改动或破坏早期编译依赖。JPEXS 按实际依赖顺序编译 Avatar、SkillSet、Buff，并验证升级界面的 GlobalFunction 和 PanelEquipBook。编译检查产物仅存放在 `build/skill-books-check`，不替代正式 Windows/Android 包或实机验收。
