# 1.0.3 阵容预设与公告适配

主页配队区域下方新增“阵容预设”入口，提供4个固定槽位。每个槽位可保存当前、覆盖保存、载入、清空；预览主队前5名英雄的头像与名称，首位队长有金色“队长”标识。空位保留位置；英雄缺失时头像变暗并显示缺失文字。

预设存放在当前账号存档的 `attrs.team_presets` 中，随现有登录、数据同步和存档备份流程保存。快照包含原生3组队伍（每组6槽）、6组装备栏、队伍选择编号及德诺阵英雄绑定；预览只展示主队前5名英雄。不会复制英雄、装备或资源。

保存从服务器已提交的当前配队读取，忽略客户端提交的替代英雄或装备数据。载入由同一个 SQLite 事务完成所有英雄、装备和德诺阵校验与切换。保存、覆盖或载入预设会给涉及的所有队伍英雄、德诺阵绑定英雄和装备自动上锁；旧预设在首次登录或写入时迁移一次。主动解锁后可以出售或消耗，缺失资产或装备栏位不再匹配时，整个载入失败，保留当前配队。清空、覆盖预设不会自动解除已有锁，避免误解锁手动保护或其他预设使用的资产。

锁状态由服务器保存并随 `state_sync` 同步，吞噬、升阶材料、出售、装备炼金及技能书材料均检查锁定。英雄使用现有锁定按钮；装备详情新增锁定/解锁按钮，装备列表显示锁图标。`user.inventory_lock` 接受明确的当前账号实例 ID、类型和布尔锁状态。手动解锁不会在下一次登录重新锁住；再次保存或载入该预设会重新启用保护。

预设只恢复分配关系：保留英雄当前等级和养成、装备当前等级和属性、德诺阵当前节点等级与解锁进度。保存后新解锁的德诺阵节点在载入旧预设时清空绑定；保存时已使用的节点若当前未解锁则拒绝载入。

接口为 `user.team_preset_save`、`user.team_preset_load`、`user.team_preset_delete`，参数 `slot` 为整数1～4，沿用 `actionID` 幂等与版本化 `state_sync`。界面阻止未完成配队操作期间再次提交，回执直接使用权威缓存，不用迟到的局部响应覆盖新状态。关闭弹窗和切换账号时清理请求监听。

主页公告的原生网页改由 `161_PanelHelpNotice.as` 统一将内容框坐标转换到当前 Starling 视口，包含横纵偏移、父级位置和缩放。弹窗居中、窗口大小或安全区变化后继续对齐网页区域；关闭后移除监听并释放本实例的网页。通用公告、图片公告与图片加载分支共用同一换算。
